# AudioShare USB v3.0.0-rc.5

Download **AudioShare-USB-Windows-v3.0.0-rc.5.zip**, extract all files into a new
folder, and run **audioshare.exe** normally. Connect your Android phone by USB,
approve USB debugging, and click Connect if it does not connect automatically.
The ZIP includes ADB and the matching signed phone companion; Android Studio
and a Windows installer are not required. Do not download Source code (zip).

## What changed

- Fixes a reproduced silent-success bug in the last-resort Windows capture
  fallback. Timer-driven capture no longer waits forever for event
  notifications that older Windows loopback implementations may never send.
- Leaves preferred global and multi-output capture unchanged.
- Shows whether Windows supplied no PCM, supplied quiet PCM, or recently
  supplied a meaningful signal. Silence never triggers a reconnect loop.
- Adds Copy report and Refresh to diagnostics, plus the Windows version,
  release label, capture fallback result, and signal state.
- Improves speakerless-PC troubleshooting and AI-assisted beginner setup.
- Adds an opt-in production-DLL-to-phone hardware test tool, separate from the
  existing protocol-only harness and Flutter tests.

## Companion compatibility

This Windows release intentionally reuses **Android v1.0.0-rc.4 (version code
7)**. The phone production code and APK are unchanged. If the exact signed RC4
companion is already installed, there is no Android update to install.

## Verification and limits

- Flutter: 41 tests and static analysis passed locally.
- Android: 37 unit tests and debug lint passed in a forced task rerun.
- Native protocol, mixer, handshake stop/error, and peer-disconnect regressions
  passed. A no-event capture regression requires real non-silent PCM.
- The exact signed companion on a Galaxy A52s / Android 14 passed a 15-second
  protocol test with 720,000 frames, zero drops, and zero underruns.
- Three 30-second production Windows DLL -> USB -> phone sessions advanced
  speaker playback and cleaned up the foreground service and exact ADB forward.
  All had zero dropped PCM frames; final Android underrun counts were 0, 7, 7.
- A Debug default-fallback run under simultaneous build load dropped 960 Android
  frames (20 ms). This is recorded, not represented as a perfect stress result.
- A separate optimized Release default-fallback run without the competing
  build completed 60 seconds with zero dropped frames and zero underruns.
  This is not proof of identical results under every scheduling load.

**Still a release candidate.** The reported work-PC silent connection has not
been retested on that PC. Physical speakers and Stereo Mix are not required
when Windows has a usable rendering endpoint, but AudioShare cannot create
sound that a source app never renders, bypass workplace restrictions, or
install missing drivers without the required permission. ASIO/exclusive/DRM
paths and two-hour endurance remain limitations or open validation gates.

If connected but silent: play a PC video for 15 seconds, click the graph icon
beside Disconnect, use **Copy report**, then Refresh and copy a second report.
See [beginner troubleshooting](https://github.com/CodeinScrubs/AudioShare/blob/main/docs/TROUBLESHOOTING.md).
